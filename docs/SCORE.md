# スコアの仕組み(解析・DB・アプリ共通の定義)

スコアの定義は、この文書を正とする。数値の実体は `config/scoring.yaml` と `config/z_rank.yaml` にあり、変えるときは、この文書と同時に直す。
企画の背景は PRD(https://claude.ai/artifact/WBfoWA11jbKuP1AUC62PKb)。

## 1. いちばん大事な決まり: 格付けは総合、内訳は分けて見せる

2026-11-14 の決定。以前の「★に分数を混ぜない」は、**格付け(Z)では総合にする**に変えた。ただし、保存と画面の内訳は、いままでどおり分ける。

| | 要因(番組の評価) | 結果(実際の睡眠) |
|---|---|---|
| 何を表すか | その回が、寝落ちに向いた作りか | その人が、何分で眠ったか |
| 記号 | 評点(🎯 🌊 🎧 の3軸) | 寝落ちまでの分数 |
| どこに保存 | `analysis` | `sleep_log` |
| 誰が決める | AI解析 + みんなの評価 | ヘルスケアの実測(watch。Apple Watch など)、自己申告(self) |

- **格付け(Z / ZZ / ZZZ)は、総合評点だけで決める**。総合評点は、AI解析を土台に、実測とみんなの評価を件数に応じて足したもの(§2 の総合評点)。
- 番組の詳細では、評点の下に**内訳を必ず出す**(バッジは、一覧ではカバー画像の右上、詳細ではタイトルの上。評点の数字の横には置かない)。例:「AI解析 4.3・ヘルスケアの実測 平均14分(8件)」。あるものだけ並べる。
- 自己申告(source=self)は、総合評点に入れない。
- **番組の評点と格付けには、起伏(🌊)と興味(🎯)の両方を判定済みの回だけを使う**(2026-11-15 の決定)。耳のゆるさ(🎧)だけの回は、重みを配り直すと高く出やすい(実データで平均 4.49、3軸そろうと 4.16)ので入れない。判定済みの回がない番組は、評点を空にし、格付けを外して掲載しない(格下げの保留もしない)。回の総合評点は内部に残す。画面では、判定がまだの観点を「判定待ち」と出す。
- 1分ごとの起伏の線(`calm_per_min`)が🌊の4項目の点と食い違うときは、線を保存しない(4項目がすべて 0 なのに 1.5 以上がある、1 以上の項目の分の前後で 0.5 未満のまま)。画面では「AIの推定」と添える。
- 「あなたの睡眠の結果」は、個人の記録として別の見出しで出す。番組の格付けには、実測の集計だけが入る。
- 睡眠の良し悪し(点数、睡眠段階、質)は評価しない。出すのは「再生してから眠るまでの分数」だけ。

## 2. 要因: 評点(1.0〜5.0)

3つの軸を合わせた点。高いほど、寝落ちに向いた作り。画面の表記は「評点」で、★と数字で出す(例 ★ 4.3。2026-11-15 変更)。AI解析だけの点は「AI解析」、全部を合わせた点は「総合評点」と呼ぶ。

| 軸 | 意味 | ★の向き | 誰が判定 | 値 |
|---|---|---|---|---|
| 🎯 程よい興味 | 続きを聞きたくなる力(引き込み力)が、ちょうどいいか | **真ん中が最良**(退屈すぎると雑念が戻り、引き込まれすぎると聞き続けてしまう) | AI(項目採点)+ みんな(10段階。件数が溜まったら、みんなの回答を優先する方向で見直す) | `interest_score`: 1〜10、`interest_level`: low(1〜3)/ mid(4〜6)/ high(7〜10) |
| 🌊 起伏の少なさ | 気持ちや頭を昂らせる強さ(感情、対立、頭の負荷、急な転換)が少ないか | **★が多いほど起伏が少ない(良い)** | AI(項目採点)+ みんな | `calm_star`: 1〜5(0.5刻み) |
| 🎧 耳のゆるさ | 話す速さ、速さのばらつき、音量の変化、突発音 | ★が多いほどゆるい(良い) | 音響の計算だけ | `ear_star`: 1〜5 |

🎯 と 🌊 の採点は「聞きながら眠れるか」で見る。AIは項目ごとに 0/1/2 を付けるだけで、★はコードが計算する(項目は `config/rubric.md`)。

| 🎯 引き込み力の項目 | 🌊 起伏の項目 |
|---|---|
| A. 未解決の問い(謎、伏線、「この後」) | A. 感情の強さ(不安・恐怖・怒りは2まで、楽しい興奮は1まで) |
| B. 驚き・新しい情報 | B. 対立・緊張 |
| C. 笑い | C. 頭の負荷(数字・固有名詞・論理の密度) |
| D. 追い続ける必要(聞き逃すと分からなくなるか) | D. 急な転換 |
| E. 聞き手への働きかけ | |

```
引き込み力 = 🎯の項目の合計(0〜10。0 のときは 1)
🎯★ = 引き込み力 4〜6 で 5.0、1 で 3.0、10 で 1.0、その間は直線(ゾーンは仮説)
🌊★ = 5 − 🌊の項目の合計 × 0.75   (下限 1.0。0.5 では実際の合計(0〜5)が 2.5〜5.0 に収まり、差が出なかった)
total = 🎯★×0.2 + 🌊★×0.5 + 🎧★×0.3   (欠けた軸は除いて重みを配り直す。重みは根拠の強さで配る: §2b。2026-11-19 に 🌊 0.6→0.5、🎧 0.2→0.3)
```

根拠の強さ(◎ 実験の積み重ね / ◯ 関連研究・理論 / △ 仮説):
- 入眠には、認知処理・認知的な駆動・努力・感情の負荷が少ないことが望ましい、という考え方(Espie & Wicklow)◯
- 不安や心配ごとを増やすと入眠までの時間が延びる ◎(🌊 A・B)
- 入眠しようとしている間に、興味を引く穏やかな課題で頭を埋めると、入眠が早まる。単調すぎる課題(羊を数える)は効果が薄い(Harvey & Payne 2002)◯(🎯 のゾーン)
- 意味を組み立てる処理は眠りを妨げ、脈絡のない思考は眠りを促す、という理論(Beaudoin)◯(🎯 D、🌊 C)
- 緊張の高まる場面は、見聞きしている最中の注意を掴む(Bezdek ほか)◯(🎯 A。睡眠は測っていない)
- 笑い、聞き手への働きかけ、ゾーンの位置、点数の配分 △
- 「見終えてから寝る」条件の研究(サスペンスドラマの視聴後に寝る、など)は、「聞きながら寝る」Neochi とは条件が違うので、判断材料にしない

解析の範囲: 回の冒頭20分(0〜10分を×3、10〜20分を×2で重く見る)。入眠までの時間の目安(15分以内がよい、Ohayon ほか 2017)に合わせている。音量のばらつきと突発音は、冒頭30分で見る(寝落ちの線の30分に合わせる。入眠後の音は、寝つきに関係しない)。

### 総合評点(`final_star`。格付けとアプリの評点はこれ)
AI解析の点を土台に、**みんなの評価は、話の内容の2軸(🎯🌊)にだけ、軸ごとに足す**。そのうえで、**実測は総合に足す**。🎧(音響の計算)には、足さない。重みは `config/scoring.yaml`(仮)。

```
みんなの🌊★ = みんなの起伏の評価(calm_vote 1〜5)の平均
みんなの🎯★ = 引き込み力の10段階(interest_rating 1〜10)を、AIと同じゾーンの式(🎯★ = 4〜6 で 5.0)で★に直した平均
              (10段階の導入前の3択 interest_vote は、退屈だった=1・ちょうどよかった=5・聴き入った=10 に読み替える。10段階があればそちらだけ)
w_みんな(軸ごと) = min(0.5, n / (n + 30))       n = その軸の評価の件数。10件未満は画面に出さず、計算にも入れない
🌊★' = 🌊★×(1 − w) + みんなの🌊★×w          🎯★' も同じ。🎧★ は計算値のまま
total' = 🎯★'×0.2 + 🌊★'×0.5 + 🎧★×0.3

実測点  = 実測の分数の中央値を 1〜5 に直した点(15分以下で 5.0、60分以上で 1.0、その間は直線。寝つき15分以下が良好、60分以上は良好でない、という合意に合わせた: Ohayon ほか 2017)
w_実測  = min(0.6, n実測 / (n実測 + 5))         n実測 = 実測の件数(source=watch)。3件未満は画面に出さず、計算にも入れない
総合評点 = total'×(1 − w_実測) + 実測点×w_実測
```
- 初期は、実測もみんなの評価も無いので、総合評点 = AI解析(`total`)。それで格付けしてよい(AI解析だけの番組も、同じ Z / ZZ / ZZZ のバッジ)。
- みんなの評価は、件数が少ないうちは出さない(過疎に見えるのを避ける)。実測はヘルスケアのデータから自動に溜まるので、みんなの評価より先に効く。
- みんなの評価が総合評点に効く量は、軸ごとの上限(0.5)と、軸の重み(🎯 0.2・🌊 0.5)から決まる。
- AI解析と実測の差が1以上なら、`final_reason` に一行の説明が入る。
- 人の手で評点を動かさない。
- 番組の評点(`show.show_star`)は、その番組の回ごとの総合評点の平均。

## 3. 結果: 寝落ちまでの分数

`latency_min` = 入眠時刻 − 再生開始時刻(分単位。入眠判定はずれるので、秒は出さない)。

入眠時刻は、音が最後に鳴っていた時刻から30分以内のものだけを使う(2026-11-20)。それより後の入眠は、聴きながらの寝落ちではない(夕方に試しで聴いた、など)ので、分数を出さず、自己申告の選択肢を出す。判定は `ios/Sources/NeochiCore/SleepAttribution.swift`。

| 分数 | 表示コメント(モック・アプリと同じ) |
|---|---|
| 10分未満 | 即落ちでした |
| 10〜20分 | 理想の寝落ちでした |
| 20〜30分 | やや粘りました |
| 30分以上 | 最後まで聴いてしまいました |

番組の詳細の「寝落ちの実績」の軸は、2つの帯で見せる(30分未満=寝落ちした、30分以上。「最後まで聴いた」とは書かない: 回の長さは作品によるので、30分以上が、最後までとは限らない)。軸の下に「再生を始めてから、30分未満で眠れた記録は、寝落ちしたとみなします。」と書く。**即落ち(短い記録)を、別の区間にも、悪い記録にもしない**(短いほど、評点の計算では実測点が高い。15分以下で満点)。平均の線は引かない(平均の分数は、見出しの数字で見せる)。

## 3b. 格付け: Z / ZZ / ZZZ(番組単位)

**総合評点だけで決める**(2026-11-14)。実測やみんなの評価の件数は、資格にしない。件数は、総合評点の重みとして効くだけ。

| 格付け | 条件(仮) | バッジ(デザイン) |
|---|---|---|
| ZZZ | 総合評点 4.5 以上 | 虹色に光る真珠 |
| ZZ | 総合評点 4.1 以上 | 青みの銀 |
| Z | 総合評点 3.6 以上 | 鈍い錫 |
| 載せない | 3.6 未満 | なし |

- 3.6 / 4.1 / 4.5 は、**割合の方針**から決めた(§3c)。根拠(研究)に基づく線ではなく、差をつけるための製品の方針。データが100件ほど溜まったら見直す。
- **基準未満の番組は、どこにも出さない**(一覧、今夜の3本、検索、番組ページ)。「圏外」とも書かない。検索で見つからないときは「まだ掲載していません」とだけ出す。評点は内部(DB)に残す。
- **格付けは、いつも評点だけで決める。格下げの保留はしない**(2026-11-16 に、実測5件までの保留をやめた)。保留があると、解析のたびに格付けが上がるだけで、評点が基準を下回っても下がらず、画面の格付けと基準が合わなくなっていた(本番100番組のうち、評点 4.0 の ZZZ など7割が不一致)。実測が少ないうちの揺れは、総合評点の重み(件数に応じて足す)で抑える。
- **採点ルールや線を変えたときは、全番組を計算し直す**(`python -m neochi z-rank --rules-changed`)。
- 番組の詳細では、バッジの横に、基準の数字ではなく、その番組をどう勧めるかのひとこと(ZZZ「眠りたい夜は、まずこの番組」、ZZ「寝落ちのために選びたい番組」、Z「寝落ちに向いた番組」)を出す(`docs/VOICE.md`。「確実に眠れる」のような約束はしない)。基準の数字は、詳細の「解析について」に書く。
- **格付けは「載せるかどうか」の基準とバッジ。見せ方の主役はランキング**(2026-11-16)。サイトのトップは、今夜の1本、2つのランキング(「寝落ち向きに作られた番組」「ふだんの番組」。振り分けは系統 genre で行い、集めた目的 cohort は使わない)、寝落ち向きの回、系統の入口の順に並べる。ランキングの順は番組の評点の高い順で、ZZ だけの棚は作らない。
- 今夜の1本(サイト)は、直近30日に公開された判定済みの回のうち、回の評点がいちばん高いもの(同点は新しい回)。該当がなければ全期間から選ぶ。アプリの「今夜の3本」は別で、下の冒険枠の決まりに従う。
- **基準未満(載せない)の番組は、新着の解析の対象から外す**(2026-11-17。`python -m neochi run`。評点がついたうえで格付けが付かなかった番組だけ。評点がまだない番組は、解析しないと評点がつかないので外さない)。外した番組も評点と過去の解析は残る。基準や採点ルールを変えたあと、もう一度見たいときは `--include-unlisted` を付ける。
- 実測が少ない番組は、アプリの今夜の3本の「冒険」枠に入れて、実測を集める。
- **評点がない回は、番組の評点の平均に入れない**。説明文だけの解析(`input_depth = meta`)は、★も根拠も付けない。回の評点が1つもない番組は、評点なし = 基準未満として、載せない。
- 番組の詳細では、評点の下に内訳を必ず出す(§1)。

## 2b. 採点は、根拠の強さで決める(2026-11-16 の決定)

**採点の数値は、睡眠の根拠の強さで決める。ラベル(寝落ち用を名乗る番組、対照群)に合わせて数値を動かさない。差をつけるのは、格付けの線(§3b。方針)で行う。** 台帳は `docs/EVIDENCE.md`、利用者向けの説明は、サイトの「スコアと根拠」(`neochi/explainer.py`)。

- 前提: 寝る前に聴く話の内容が、寝落ちを早めることの証拠は、まだ弱い(音楽でも、自己申告では短くなる可能性があるが、機器で測ると差が見られない、という結果が混ざる)。評点は「眠れる」の約束ではなく、「妨げになりそうな要素が少ないか」の推定。最終の裏付けは、ヘルスケアの実測。
- 根拠の強さは ◎◯△ で言う(VOICE.md の「説明」の決まり)。◎ 実験の積み重ね(現在、該当なし)、◯ 関連研究(寝つきを測った研究があるが、自分の考えごと・夜間の騒音などで、聴く話そのものではない)、△ 仮説(研究が見つかっていない)。説明ページは、短い事実の文で書き、物語らない(VOICE.md §2・§3)。
- 重みは強さで配る: 軸は 🌊 0.6(研究から推論の項目が多い)、🎯 0.2、🎧 0.2。🎧の中は、突発音 0.4(研究から推論)、他の3つ 各 0.2(仮説)。**2026-11-19 に、🌊 0.5、🎯 0.2、🎧 0.3 に変えた**(下の「重みの変更」)。
- 仮説の基準値(話す速さ 290/450字、ばらつき、音量 4/12dB、🎯 のゾーン 4〜6、各項目の重み)は、データに合わせて動かさない。実測が集まったら、残すか外すかを決める。
- この決定のきっかけ: 同日に、対照群(寝落ち用ではない教養トーク)に合わせて話す速さの基準と🎧の重みを動かしたが(ef8f2c5)、ラベルは眠れたことの証拠ではなく、根拠の強い突発音の重みを下げる、逆向きの変更だったので、戻した。

## 3c. 格付けの線: 割合の方針(2026-11-16)

2026-11-15 の掲載97番組(最新の話の判定)で、ZZZ が 73% だった(線は 3.0 / 3.6 / 4.2。評点の中央値 4.2 に7割が集まっていた)。

- 原因は、(1) 🌊の幅が狭く(合計×0.5 だと 2.5〜5.0 に収まる)、(2) 重みが、根拠の強さと関係なく配られていたこと(仮説の 🎯 ゾーンが 0.3、仮説の多い 🎧 が 0.3)。
- 直し方: 🌊 を ×0.75 に、重みを 🎯 0.2 / 🌊 0.6 / 🎧 0.2 に(§2b)。🎧の基準値は元に戻した。
- 線は、判定済みの番組の中で、**上位およそ15%が ZZZ、上位およそ45%までが ZZ 以上、上位およそ80%までが Z 以上**という割合の方針から決めた: 4.5 / 4.1 / 3.6。試算(97番組の最新の話): ZZZ 15%、ZZ 29%、Z 36%、載せない 20%。
- 注意: 試算は1つの話ぶんで、番組の評点(話の平均)はもう少し真ん中に寄る。本番で `python -m neochi z-rank --rules-changed` を実行したあと、割合を確かめる。外れていたら、割合の方針のほうに、線を合わせ直す。
- `tests/test_calibration.py` が、重みの向き、極端な2つの話の向き、割合の幅を確かめる。ラベルを正解にした検査はしない。

## 4. 朝の振り返り: アプリで聞くことと、DBの値

入力は2つ + 任意のメモ。「記録する」を押したときだけ保存する。質問はすべて任意で、答えなくても記録できる。

| 画面の項目 | 入力 | DBの値 | 何に使うか |
|---|---|---|---|
| 興味 | 「この話に、どれくらい引き込まれましたか」。**10段階**(1 ほとんど引き込まれない 〜 10 続きが気になって仕方ない)。触るまで未入力 | `interest_rating`(1〜10。`0011_interest_rating.sql`。旧3択の `interest_vote` は導入前の行だけ) | 総合評点に混ぜる「みんなの🎯★」(§2) |
| 起伏 | 「聴いていて、盛り上がりや驚きはありましたか」。両端に言葉のある**5段階**(1 たくさんあった 〜 5 ほとんどなかった)。同じ値をもう一度押すと未入力 | `calm_vote`(1〜5) | 総合評点に混ぜる「みんなの🌊★」(§2) |
| メモ | 自由記入(任意) | `note` | 集計には使わない |

- **数字とゾーンの意味は、入力の画面で必ず見せる**(AIの🎯と同じ区切り。`NCString.interestZone` と `config/scoring.yaml` の interest_zone を揃える)。数字だけを並べない。選んだ数字のゾーンは太字にし、色だけに頼らず言葉で書く。

  | 数字 | ゾーン | 意味 |
  |---|---|---|
  | 1〜3 | 退屈寄り | 気が散って、別のことを考えてしまう(★は下がる) |

- 分数は聞かない。ヘルスケアの実測があれば `source=watch`、なければ自己申告で `source=self`。自己申告は、4つの選択肢(すぐ寝た・少し起きていた・なかなか寝つけなかった・最後まで聴いた)で聞き、内部でおおよその分数(5・15・25・40分)に直して `latency_min` に入れる(2026-11-16)。評点・格付けの集計には入れない。

## 判定基準 v2(案)と、移行の手順(2026-11-19)

🌊🎯の判定を、**点ではなく観察(分と引用つき)を出させ、点はコードが計算する**形に変える案。定義は `config/rubric_v2.md`、根拠は `docs/EVIDENCE.md` の「判定基準 v2」、点の計算は `neochi/observe.py`(数値は `config/observe.yaml`、仮)。**まだ本番では使っていない**(本番は `config/rubric.md` と `config/scoring.yaml`)。

移行の手順:
1. (済み)文字起こしの保存と、版の記録(`transcript` 表、`reasons.versions`)。定義を変えたとき、判定だけやり直せる(`docs/OPERATIONS.md` §7)。
2. (済み)v2 の定義と、観察を点にする計算。
3. 確かめ用の20〜30回で、v2 の判定を試す。点の出方(満点が出すぎないか、判定者のぶれ、いまの点との違い)を見て、`observe.yaml` の数値を決める。
4. 全件を、v2 で判定し直す(`run --force` で文字起こしを取り直し、以後は `repending`)。パイプライン、サイト、アプリの画面(項目の表示)を、v2 に切り替える。

### 判定の安定性の確かめ(2026-11-19。同じ回を2人が独立に判定して、ぶれを測る)

確かめ用の29回(`data/check_set_v2.json`)で、旧の基準と v2 を、同じ見方で比べた。ぶれ ÷ 幅 は、2人の点の差の平均を、点の幅(標準偏差)で割ったもの(小さいほど安定。基準によって点の刻みが違うので、この割合で比べる)。順位相関は、2人の順位の一致(大きいほど安定)。

| 同じ17回(割れた回を選んでいない) | 🌊 ぶれ÷幅 | 🌊 順位相関 | 🎯 ぶれ÷幅 | 🎯 順位相関 |
|---|---|---|---|---|
| 旧の基準(`config/rubric.md`) | 0.53 | 0.54 | 0.73 | 0.26 |
| v2.1 | 0.52 | 0.72 | 0.30 | 0.94 |
| v2.2 | 0.67 | 0.40 | 0.47 | 0.91 |

- **🎯は、v2 のほうが、はっきり安定している**(順位の一致 0.26 → 0.9 台)。旧の🎯(引き込み力 1〜10 の点)は、同じ回でも、2人で 2.0 と 5.0 に割れる回がある。
- **🌊は、旧と v2.1 で、ぶれ÷幅が同じ**(0.52、0.53)。順位の一致は、v2.1 のほうがよい(0.72 と 0.54)。
- **v2.2 は、v2.1 より安定しなかった**ので、取り下げた。「1分でも見落とさず挙げる」などが、穏やかな内容まで拾わせて、判定者による差を広げた可能性がある(原因は、まだ分けて確かめていない)。round3 の改善は、割れた回を選んだことによる見かけ(平均への回帰)だった。
- 点の計算の直し(感情の加点を区間の長さに左右されない形に、1分あたりの上限)は、判定をやり直さずに効く(オフラインで確かめた)ので、残した。
- 注意: ここで測ったのは、**判定の安定性(同じ回を2人が判定して、同じ点になるか)**で、点が**正しいか**(実際の寝落ちと合うか)ではない。後者は、ヘルスケアの実測がたまってから確かめる。

### 重みの変更(2026-11-19)

🎯🌊🎧の重みを、0.2 / 0.6 / 0.2 から **0.2 / 0.5 / 0.3** にした。格付けの線(4.5 / 4.1 / 3.6)は、そのまま。
- 理由: 🌊は根拠がいちばん強い軸(台帳)だが、AI判定のぶれがある。🎧は機械で測るので、誰が測っても同じ値になる。
- 本番の261番組での試算(解析済みの回の平均): 番組どうしの差(点の幅)0.54 → 0.46、判定者のぶれによる揺れ ±0.22 → ±0.18。**揺れ÷幅は 0.40 のまま**(番組を見分ける力は、変わらない)。
- **🌊の重みを 0.3 以下に下げる案は、取らなかった**。🌊は、番組どうしの差がいちばん大きい軸(幅 0.94。🎯 0.67、🎧 0.31)で、重みを下げると、番組の差が、揺れより速く縮む(0.3 / 0.3 / 0.4 で、幅 0.30、揺れ÷幅 0.53)。
- **🎧の重みを 0.5 にする案も、取らなかった**。台帳では、🎧の中で根拠が ◯ なのは突発音(重み 0.4)だけで、残り 0.6 は仮説(△)。根拠の強さと、測り方の信頼性(誰が測っても同じ)は、別のこと。🎧 0.5 にすると、半分の番組が ZZ になる(今の線で ZZ 51%、載せない 3%)。
- 今の線での割合(試算): ZZZ 25%、ZZ 29%、Z 34%、載せない 12%。以前は、ZZZ 25%、ZZ 24%、Z 32%、載せない 20%。

### 🎯の判定を、観察に切り替えた(2026-11-20)

🎯(程よい興味)の判定を、旧の「5項目を 0〜2 点で採点 → 引き込み力 1〜10 → ゾーンで★」から、**観察(分と引用つき)を出させ、点はコードが計算する**形に切り替えた。🌊(起伏)は、旧の項目(A〜D)のまま。理由は、上の「判定の安定性の確かめ」(🎯は、順位の一致が 0.26 から 0.94 に上がった)。
- 判定の形式: `config/rubric.md` の🎯。`hook`(先が気になる)、`follow`(追い続ける必要)、`imagery`(思い浮かぶ具体性)を、分と引用つきで出す。3つの配列は、空でも必ず書く(`imagery` の書き忘れを、退屈として減点しないため。書いていなければ、取り込まない)。
- 点: 🎯★ = 5 − 先を引っぱる減点 − 筋の減点 − 退屈の減点(思い浮かぶ具体的な話が、冒頭の半分に満たない分)。下限 1.0。数値は `config/observe.yaml`(仮)。**点は保存せず、保存済みの観察から、そのつど計算する**ので、数値を直せば、判定をやり直さずに、全部の回に反映される(`z-rank --rules-changed`)。
- 保存: 観察は `analysis.reasons.interest_obs`(列の追加なし)。`interest_score`(1〜10)は付けない。`interest_level`(low / mid / high)は、観察から決める(low = 退屈側、high = 引き込まれすぎ側)。
- 旧の形式の回(`interest_score` と `items.interest` を持つ回)は、そのまま読める。旧の回を、観察で判定し直すと、前の項目と点は、置き換わる(`repending --stale` で、古い基準の回を見つけられる)。
- みんなの🎯の評価(1〜10)は、これまでどおり、ゾーンの式で★に直して、AIの🎯★に足す。
- 画面: サイトの詳細ページは、観察(件数・分数・引用)を出す。「スコアと根拠」のページも直した。**アプリ(iOS)の🎯の項目の表示は、まだ直していない**(`reasons.interest_obs` を読む必要がある)。それまで、観察で判定した回は、🎯の項目の一覧が、空に見える。
