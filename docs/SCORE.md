# スコアの仕組み(解析・DB・アプリ共通の定義)

スコアの定義は、この文書を正とする。数値の実体は `config/scoring.yaml` と `config/z_rank.yaml` にあり、変えるときは、この文書と同時に直す。
企画の背景は PRD(https://claude.ai/artifact/WBfoWA11jbKuP1AUC62PKb)。

## 1. いちばん大事な決まり: 格付けは総合、内訳は分けて見せる

2026-11-14 の決定。以前の「★に分数を混ぜない」は、**格付け(Z)では総合にする**に変えた。ただし、保存と画面の内訳は、いままでどおり分ける。

| | 要因(番組の評価) | 結果(実際の睡眠) |
|---|---|---|
| 何を表すか | その回が、寝落ちに向いた作りか | その人が、何分で眠ったか |
| 記号 | 評点(🎯 🌊 🎧 の3軸) | 寝落ちまでの分数 |
| どこに保存 | `analysis` | `sleep_log` |
| 誰が決める | AI解析 + みんなの評価 | Apple Watch の実測(watch)、自己申告(self) |

- **格付け(Z / ZZ / ZZZ)は、総合評点だけで決める**。総合評点は、AI解析を土台に、実測とみんなの評価を件数に応じて足したもの(§2 の総合評点)。
- 画面では、バッジの横に**内訳を必ず出す**。例:「AI解析 4.3・ウォッチの実測 平均14分(8件)」。あるものだけ並べる。
- 自己申告(source=self)は、総合評点に入れない。
- 「あなたの睡眠の結果」は、個人の記録として別の見出しで出す。番組の格付けには、実測の集計だけが入る。
- 睡眠の良し悪し(点数、睡眠段階、質)は評価しない。出すのは「再生してから眠るまでの分数」だけ。

## 2. 要因: 評点(1.0〜5.0)

3つの軸を合わせた点。高いほど、寝落ちに向いた作り。画面の表記は「評点」(★は使わない)。AI解析だけの点は「AI解析」、全部を合わせた点は「総合評点」と呼ぶ。

| 軸 | 意味 | ★の向き | 誰が判定 | 値 |
|---|---|---|---|---|
| 🎯 程よい興味 | 続きを聞きたくなる力(引き込み力)が、ちょうどいいか | **真ん中が最良**(退屈すぎると雑念が戻り、引き込まれすぎると聞き続けてしまう) | AI(項目採点)+ みんな | `interest_score`: 1〜10、`interest_level`: low(1〜3)/ mid(4〜6)/ high(7〜10) |
| 🌊 起伏の少なさ | 気持ちや頭を昂らせる強さ(感情、対立、頭の負荷、急な転換)が少ないか | **★が多いほど起伏が少ない(良い)** | AI(項目採点)+ みんな | `calm_star`: 1〜5(0.5刻み) |
| 🎧 耳のゆるさ | 話す速さ、速さのばらつき、音量の変化、突発音 | ★が多いほどゆるい(良い) | 音響の計算だけ | `ear_star`: 1〜5 |

🎯 と 🌊 の採点は「聞きながら眠れるか」で見る。AIは項目ごとに 0/1/2 を付けるだけで、★はコードが計算する(項目は `config/rubric.md`)。

| 🎯 引き込み力の項目 | 🌊 起伏の項目 |
|---|---|
| A. 未解決の問い(謎、伏線、「この後」) | A. 感情の強さ(不安・恐怖・怒りは2まで、楽しい興奮は1まで) |
| B. 驚き・新しい情報 | B. 対立・緊張 |
| C. 笑い | C. 頭の負荷(数字・固有名詞・論理の密度) |
| D. 追い続ける必要(聞き逃すと分からなくなるか) | D. 急な転換 |
| E. 聞き手への働きかけ | |

```
引き込み力 = 🎯の項目の合計(0〜10。0 のときは 1)
🎯★ = 引き込み力 4〜6 で 5.0、1 で 3.0、10 で 1.0、その間は直線(ゾーンは仮説)
🌊★ = 5 − 🌊の項目の合計 × 0.5
total = 🎯★×0.3 + 🌊★×0.4 + 🎧★×0.3   (欠けた軸は除いて重みを配り直す)
```

根拠の強さ(◎ 実験の積み重ね / ◯ 関連研究・理論 / △ 仮説):
- 入眠には、認知処理・認知的な駆動・努力・感情の負荷が少ないことが望ましい、という考え方(Espie & Wicklow)◯
- 不安や心配ごとを増やすと入眠までの時間が延びる ◎(🌊 A・B)
- 入眠しようとしている間に、興味を引く穏やかな課題で頭を埋めると、入眠が早まる。単調すぎる課題(羊を数える)は効果が薄い(Harvey & Payne 2002)◯(🎯 のゾーン)
- 意味を組み立てる処理は眠りを妨げ、脈絡のない思考は眠りを促す、という理論(Beaudoin)◯(🎯 D、🌊 C)
- 緊張の高まる場面は、見聞きしている最中の注意を掴む(Bezdek ほか)◯(🎯 A。睡眠は測っていない)
- 笑い、聞き手への働きかけ、ゾーンの位置、点数の配分 △
- 「見終えてから寝る」条件の研究(サスペンスドラマの視聴後に寝る、など)は、「聞きながら寝る」Neochi とは条件が違うので、判断材料にしない

解析の範囲: 回の冒頭20分(0〜10分を×3、10〜20分を×2で重く見る)。入眠までの時間の目安(15分以内がよい、Ohayon ほか 2017)に合わせている。音量のばらつきと突発音は、冒頭30分で見る(寝落ちの線の30分に合わせる。入眠後の音は、寝つきに関係しない)。

### 総合評点(`final_star`。格付けとアプリの評点はこれ)
AI解析の点を土台に、**みんなの評価は、話の内容の2軸(🎯🌊)にだけ、軸ごとに足す**。そのうえで、**実測は総合に足す**。🎧(音響の計算)には、足さない。重みは `config/scoring.yaml`(仮)。

```
みんなの🌊★ = みんなの起伏の評価(calm_vote 1〜5)の平均
みんなの🎯★ = 興味の3択(interest_vote)を、退屈だった 3.0 / ちょうどよかった 5.0 / 聴き入った 1.0 に直した平均
              (ゾーンの式の両端に合わせる)
w_みんな(軸ごと) = min(0.5, n / (n + 30))       n = その軸の評価の件数。10件未満は画面に出さず、計算にも入れない
🌊★' = 🌊★×(1 − w) + みんなの🌊★×w          🎯★' も同じ。🎧★ は計算値のまま
total' = 🎯★'×0.3 + 🌊★'×0.4 + 🎧★×0.3

実測点  = 実測の分数の中央値を 1〜5 に直した点(10分以下で 5.0、40分以上で 1.0、その間は直線)
w_実測  = min(0.6, n実測 / (n実測 + 5))         n実測 = 実測の件数(source=watch)。3件未満は画面に出さず、計算にも入れない
総合評点 = total'×(1 − w_実測) + 実測点×w_実測
```
- 初期は、実測もみんなの評価も無いので、総合評点 = AI解析(`total`)。それで格付けしてよい(AI解析だけの番組も、同じ Z / ZZ / ZZZ のバッジ)。
- みんなの評価は、件数が少ないうちは出さない(過疎に見えるのを避ける)。実測はウォッチで自動に溜まるので、みんなの評価より先に効く。
- みんなの評価が総合評点に効く量は、軸ごとの上限(0.5)と、軸の重み(🎯 0.3・🌊 0.4)から、最大でも約0.35。
- AI解析と実測の差が1以上なら、`final_reason` に一行の説明が入る。
- 人の手で評点を動かさない。
- 番組の評点(`show.show_star`)は、その番組の回ごとの総合評点の平均。

## 3. 結果: 寝落ちまでの分数

`latency_min` = 入眠時刻 − 再生開始時刻(分単位。入眠判定はずれるので、秒は出さない)。

| 分数 | 表示コメント(モック・アプリと同じ) |
|---|---|
| 10分未満 | 即落ちでした |
| 10〜20分 | 理想の寝落ちでした |
| 20〜30分 | やや粘りました |
| 30分以上 | 最後まで聴いてしまいました |

## 3b. 格付け: Z / ZZ / ZZZ(番組単位)

**総合評点だけで決める**(2026-11-14)。実測やみんなの評価の件数は、資格にしない。件数は、総合評点の重みとして効くだけ。

| 格付け | 条件(仮) | バッジ(デザイン) |
|---|---|---|
| ZZZ | 総合評点 4.2 以上 | 虹色に光る真珠 |
| ZZ | 総合評点 3.6 以上 | 青みの銀 |
| Z | 総合評点 3.0 以上 | 鈍い錫 |
| 載せない | 3.0 未満 | なし |

- 3.0 / 3.6 / 4.2 は、100点満点で 50 / 65 / 80 に当たる。データが100件ほど溜まったら見直す。
- **基準未満の番組は、どこにも出さない**(一覧、今夜の3本、検索、番組ページ)。「圏外」とも書かない。検索で見つからないときは「まだ掲載していません」とだけ出す。評点は内部(DB)に残す。
- 格下げは、実測が5件以上になってから見直す。それまでは、AI解析で付いた格付けを動かさない。これは、**実測が少ないうちの記録の揺れで、格付けが上下しない**ための決まりに限る。
- **採点ルールや線を変えたときは、この引き継ぎを使わず、全番組を計算し直す**(`python -m neochi z-rank --rules-changed`)。古いルールで付いた格付けを、そのまま残さない。
- 実測が少ない番組は、今夜の3本の「冒険」枠に入れて、実測を集める。
- **評点がない回は、番組の評点の平均に入れない**。説明文だけの解析(`input_depth = meta`)は、★も根拠も付けない。回の評点が1つもない番組は、評点なし = 基準未満として、載せない。
- バッジの横には、内訳を必ず出す(§1)。

## 4. 朝の振り返り: アプリで聞くことと、DBの値

入力は2つ + 任意のメモ。「記録する」を押したときだけ保存する。質問はすべて任意で、答えなくても記録できる。

| 画面の項目 | 入力 | DBの値 | 何に使うか |
|---|---|---|---|
| 興味 | 「この回の話は、どうでしたか」。**3択**: 退屈だった(-1)/ ちょうどよかった(0)/ 聴き入った(1)。触るまで未入力 | `interest_vote`(-1 / 0 / 1。`0001_init.sql` の check 制約。スライダーにすると制約違反になる) | 総合評点に混ぜる「みんなの🎯★」(§2) |
| 起伏 | 「話の流れは、ゆるやかでしたか」。両端に言葉のある**5段階**(1 起伏が多かった 〜 5 ゆるやかだった)。同じ値をもう一度押すと未入力 | `calm_vote`(1〜5) | 総合評点に混ぜる「みんなの🌊★」(§2) |
| メモ | 自由記入(任意) | `note` | 集計には使わない |

- 分数は聞かない。ヘルスケアの実測があれば `source=watch`、なければ自己申告で `source=self`。
- 睡眠のスコアや評価は出さない(入眠の時刻だけ)。

## 5. 画面での言葉

- 「寝落ち格付け」は、Z / ZZ / ZZZ の呼び名。「寝落ちスコア」は仕組み全体の呼び名で、画面には出さない。画面に1つの点として出すのは、総合評点。
- 結果の分数には、「良い・悪い」ではなく、上の表のコメントを使う。
- 診断に見える言葉(不眠、改善、効果、治る など)は使わない。根拠は誇張しない。
- 点数の意味は、ⓘ から開く説明にまとめる(評点の3軸、分数、Z)。

## 6. 分析の詳細(アプリで見せるデータ)

各回の `analysis` には、★だけでなく、根拠になったデータを保存する。アプリの番組・回の詳細で、項目ごとに見せる。

| 何を見せるか | 保存場所(`analysis` の列 → キー) | 単位・範囲 | 見せ方の案 |
|---|---|---|---|
| 🎧 の内訳★ | `features.ear_parts` → `rate` / `rate_cv` / `volume` / `sudden` | 各 1〜5 | 4項目の★を並べる(話す速さ / 速さのばらつき / 音量の変化 / 突発音) |
| 話す速さ | `features.speech_rate`(前半重み付き)、`features.timeline.rate_per_min` | 日本語は 字/分。冒頭20分のみ。発話が少ない分は null | 1分ごとの折れ線。満点の上限(290字/分)に線を引く |
| 速さのばらつき | `features.speech_rate_cv` | 0〜(0.10 で満点、0.40 で最低) | 数字は出さず、内訳★と一言で |
| 音量の変化 | `features.volume_std_db`、`features.timeline.volume_db` | 1分ごとの、冒頭30分の中央値との差(dB)。冒頭30分。無音の分は null | 0 を中心にした折れ線。上下の幅が小さいほどゆるい |
| 突発音 | `features.sudden_per_10min`、`features.timeline.sudden_at_sec` | 回数/10分、起きた秒(最大300件)。冒頭30分 | 音量の折れ線の上に印 |
| 🌊🎯 の根拠 | `reasons.llm`、`interest_score`、`interest_level`、`calm_star` | 60字以内の一行 | 軸の★の下に一行 |
| 🌊🎯 の項目ごとの点 | `reasons.items.interest` / `reasons.items.calm` → 各項目 `{score: 0〜2, min: 分 or null}` | | 項目を並べ、1以上の項目は該当する分に印 |
| 目立つ箇所 | `reasons.moments` → `[{min, note}]`(最大3件) | 冒頭20分の中の分 | 🎧 のグラフの時間軸に、印と一言を重ねる |
| 解析の深さ | `input_depth` | audio = 音響のみ / transcript = 文字起こしあり / meta = 説明文のみ | 「どこまで解析したか」の注記 |
| 長さ | `features.duration_sec` | 秒 | |

注意:
- 話す速さは冒頭20分、音量と突発音は冒頭30分。グラフの横軸の長さが違うので、同じ図に重ねるときは時間軸をそろえる。長さ(`duration_sec`)は回全体。
- **2026-11-15 より前の解析は、音量と突発音を全編で測っている。** 冒頭30分に直すには、音響だけを測り直す(`python -m neochi remeasure`。🌊🎯と話す速さは触らず、終わったら番組の評点と格付けも計算し直す)。
- 突発音は、屋外の環境音や効果音の多い回で、多めに数えることがある。数値は「目安」として見せる。
- 音量は相対値(dB差)。大きい・小さいの絶対値ではない。中央値は、冒頭30分のもの。
- 2026-11-13 より前の解析には、`timeline` と `ear_parts` がない。無いときは、その表示を出さない。
