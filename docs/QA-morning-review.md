# QA報告: 朝の振り返りの実装と、スコアの定義(`docs/SCORE.md`)の食い違い

作成: 開発側(iOS) / 対象: iOS アプリ MVP の朝の振り返り画面 / 状態: 議論用のたたき台
改訂: 初版は `SCORE.md` と `0004_sleep_log_app.sql` を読む前に書いた。両方を読んだうえで、全面的に書き直した。

## 1. 要約

- **定義は、すでに決まっている**(`docs/SCORE.md` が「解析・DB・アプリ共通の定義」の正)。食い違っているのは、**iOS の実装が、その仕様に追いついていない**点。
- 初版で指摘した「記録がサーバーに送れない」(権限がない、列がない)は、`0004_sleep_log_app.sql` で解決している。**ただし、本番の DB に適用されているかは、未確認。**
- iOS 側に残る問題は5つ(下の 3)。うち最も重いのは、**興味を 0〜100 で送ると、DB の制約違反になる**こと。

確認の区分: コード、SQL、文書を読んで確認したもの。実際の Supabase への送信は、していない。

## 3. 開発側の指摘

- **A. 興味の送信が、DB の制約に違反する(確定)。**
  `interest_vote` は、-1、0、1 のみ(`0001_init.sql` の check 制約)。iOS は 0〜100 の値を送る(`SupabaseClient.swift` 157〜164行目)。スライダーに触れた記録は、制約違反になる。`SCORE.md` §4 にも、「スライダーにしない。制約違反になる」と明記されている。
- **B. 送信の失敗が、握りつぶされる。**
  `Task { try? await SupabaseClient.shared.upload(log) }`(`AppModel.swift` 139行目)。失敗しても、画面にも開発側にも、何も出ない。再送もしない。
- **C. 送信できる状態かは、未確認。**
  `0004_sleep_log_app.sql` が、`note`・`listen_no`・`user_id` の列と、「自分の行だけ」の policy を足す。前提は、Supabase の「Allow anonymous sign-ins」をオンにすること。本番に適用されているか、確認が必要。
- **D. 画面の読み違い。**
  興味は、真ん中が最良(`SCORE.md` §2)。画面は「興味」とだけ出し、数字が大きいほど良い、と読める。起伏も、★が多いほど良い(起伏が少ない)ことが、画面で分からない。
- **E. 軸の名前が、文書と画面でずれている。**
  文書は「耳のゆるさ」(★が多い = ゆるい = 良い)。画面は「耳ざわり」。「耳ざわり」の★が多いと、耳障りが強い、と逆に読める。興味も、画面は「興味」で、文書は「程よい興味」。
- **F. 結果のコメントが、文書・コード・禁止語の検査で、三つ巴になっている。**
  - `SCORE.md` §3 の表は、「スプーン」を使う。
  - 禁止語の検査(`tests/test_strings.py`)は、「🥄」と「スプーン」を禁止する。検査の対象は、`neochi/*.py`、`config/*`、`0001_init.sql` で、`docs/` は含まない。
  - 実際のコード(`strings.py`、`Strings.swift`)は、「即落ちでした」「理想の寝落ちでした」を使う。
  - 「それは動画の力ではなく」(文書)と「それは番組の力ではなく」(コード)も、違う。

## 4. 朝の振り返りの「グラフ」について

ユーザーの記憶では、「関係する睡眠データを、グラフで出す」ことになっていた。`SCORE.md` §6 に、分析の詳細(1分ごとの推移、突発音、目立つ箇所)のグラフはあるが、それは**番組・回の詳細**の話で、「その人の睡眠データ」ではない。朝の振り返りで、その人の睡眠データのグラフを出す仕様は、見つからなかった。

出すなら、ヘルスケア側の方針(「睡眠の評価(点数、段階、質)はしない」)の範囲で、再生開始から入眠までの時間軸(再生開始、入眠、再生が止まった時刻)が、案になる。要議論。

## 5. 議論したいこと(開発側の推奨つき)

1. **興味と起伏の入力を、`SCORE.md` §4 に合わせて作り直す。**
   推奨: 興味は3択(退屈だった / ちょうどよかった / 聴き入った)、起伏は両端に言葉を置いた5段階。標準の部品(`Picker` など)にする。DB は変えない。
2. **朝の振り返りの構成。**
   推奨: 標準の `Form` で、見出しを分ける。①あなたの睡眠の結果(分数、データの出どころ) ②番組について(質問。各質問に見出しと説明) ③メモ ④記録する。評価のひとことは、結果の下に、評価として区別して置く。
3. **朝の振り返りに、その人の睡眠データのグラフを出すか。** 出すなら、何を。
4. **軸の名前をそろえる。** 「耳ざわり」→「耳のゆるさ」、「興味」→「程よい興味」。
5. **結果のコメントの文言を、一本化する。** 「スプーン」を使うか(禁止語の検査との整合も取る)、今のコードの文言にそろえて、文書を直すか。
6. **送信の失敗の扱い。** 失敗を記録し、再送する。ユーザーには、必要なときだけ知らせる。
7. **本番の DB に `0004`、`0005` が適用されているか、確認する。**
