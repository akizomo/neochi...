# フリーミアムの設計(課金構造・線引き・実装計画)

2026-11-16 の議論をまとめたもの。**価格と数字はすべて仮説**(根拠は各所に書く)。決まっていないことは末尾の「決めること」。

## 1. 結論

- **商品は1つ。** 自動更新のサブスクリプション「NeochiPickzz プレミアム」。月額と年額の2つの買い方だけ。買い切り・複数の段・広告は、最初は置かない。
- **売るもの:** 「Player が賢くなる」。本編から静かに始まり、再生中は寝落ちしやすいあたりが見え、自分に合う番組が並ぶ。
- **売らないもの:** 番組そのもの(他人のコンテンツ)と、データを生む行動(記録・評価・朝の振り返り)。
- **順番:** 1.0 は無料だけで出して記録を集め、1.1 で課金を入れる(理由は §7)。

## 2. 商品と価格(仮説)

| | 価格(税込) | 位置づけ |
|---|---|---|
| 年額 | 1,500円(月あたり125円) | 主力。ペイウォールで先に見せる。14日の無料トライアルつき |
| 月額 | 200円 | 年額を安く見せる比較の相手。トライアルなし |

- **なぜ年額を主力にするか:** 寝落ちは毎晩の習慣で、価値は数週間使って分かる。月額は「今月は使わなかった」で解約されやすい。
- **なぜトライアルは14日か:** 1晩に1回しか試せない。7日では、パーソナライズに要る記録(5件〜)がたまらない。
- **なぜ買い切りを置かないか:** 解析の費用(サーバー、LLM)は毎月かかる。買い切りは収入が先細る。要望が多ければ、あとから足す(足すのは簡単、やめるのは難しい)。
- **この価格にした理由(2026-11-16):** 最初の案(年額 3,800円・月額 480円)は、いまの機能には高い。売るのは「再生が便利になる機能」で、自前のコンテンツはない。比べる相手は睡眠アプリではなく、ポッドキャストアプリの有料版(年に千円台)。いまは売上より、記録を続ける人を増やすほうが大事。機能が育ったら、新しい契約者だけ値上げする(高く出して下げると、先に払った人が損をする)。
- **価格の根拠は弱い。** 相場から置いた数字で、検証していない。App Store Connect では、公開後に価格を変えられる(既存の契約者の扱いは選べる)。まずこの値で出して、トライアル開始率と継続率を見る。

## 3. 無料と有料の線引き

### 原則

1. **データを生む行動は、すべて無料。** 寝落ちの記録(ヘルスケア)、みんなの評価、朝の振り返りは、総合評点と格付けの材料。ここを有料にすると、みんな10件・実測3件の基準(`SCORE.md`)に届かなくなる。**無料ユーザーは、評点を育てる協力者。**
2. **みんなの答えは無料、「自分の場合」は有料。** 番組の評点・格付け・分析の詳細は、サイトと同じく無料(集客の入口でもある)。自分の記録から導いた解釈と最適化を有料にする。
3. **番組そのものには値段をつけない。** 再生・番組・回を有料の壁の向こうに置かない。売るのは、アプリが足した機能(解析、Player の賢さ)だけ。他人のコンテンツで課金している、と見られないために。
4. **サーバーで原価が出る機能は、有料かつ回数に上限。** いま該当するのは、解析のリクエストだけ。

(前の版の原則3「ユーザーごとに原価が出るものは有料」は、4 に直した。パーソナライズは端末内の計算で作れるので、原価は出ない。有料にする理由は原価ではなく、原則2。)

### 範囲

| | 無料 | プレミアム |
|---|---|---|
| 探す | 一覧、総合評点、Z/ZZ/ZZZ、系統の棚、今夜の1本(全員共通の並び) | **あなた向けの並び。** 自分の寝落ちの実績で、今夜の1本と棚を並べ直す |
| 聴く | 普通の再生、スリープタイマー | **本編から始める**(§3.1)、**Player の寝落ちグラフ**(§3.2) |
| 回の詳細 | 起伏・話す速さ・音量・突発音の静的なグラフ(`SCORE.md` §6) | — |
| 記録 | 寝落ちの記録、分数、朝の振り返り、直近30日の履歴、Apple ログイン(引き継ぎ) | 全期間の傾向(`BACKLOG.md` の記録タブ)、書き出し |
| 解析 | 解析済みの番組を見る | 解析のリクエスト(月◯本まで。結果は全員に公開)。**後回し**(§7 の段階5) |

アカウント(Apple ログイン)と記録の引き継ぎは無料。購入にログインは要らない(§6)。

### 3.1 本編から始める

冒頭のジングル・告知・広告を飛ばし、ストレスなく聴き始められるようにする。打ち出しは「広告スキップ」ではなく「静かに始める」。

- **検出(実装済み):** 判定が `content_start`(秒と、本編の最初の一言)を出す → analysis の `content_start_sec` / `content_start_anchor`(`0009_content_start.sql`、未適用)。冒頭5分に見つからなければ null で、アプリは飛ばさない。
- **位置合わせ:** 動的広告挿入で、解析した音声と再生する音声の開始秒がずれる。
  - v1: 秒でそのまま移動し、「本編から再生しています／冒頭に戻す」を出す(外れても、1タップで戻れる)。**先に、秒がどのくらいずれるかを実測する**(同じ回を日を変えて2回落として比べる)。
  - v2: ずれが大きい番組があれば、最初の一言を端末内の音声認識で照合する。
- **お試しは置かない。** 前の版の「無料でも毎晩1回」は取り下げる。1晩に聴くのはふつう1回なので、実質すべて無料になる。試すのは14日のトライアルで。

### 3.2 Player の寝落ちグラフ

番組の起伏(`calm_per_min`)・話す速さ・音量を、再生位置と連動して出し、寝落ちしやすいエリアを帯で重ねる。タップでその位置へ移動できる。

寝落ちしやすいエリアの出どころは、データの量で切り替える。

1. 実測が少ないうち: 起伏・音量・話速が落ち着いた区間を「AIの推定」として出す。
2. 実測がたまったら: ヘルスケアの実測の寝落ち位置を回ごとに集め、「みんなが寝落ちしたあたり」の分布にする(少人数の回は出さない。個人が分かるため)。
3. 自分の過去の寝落ち位置と、自分の傾向からの予測を重ねる。

無料の回の詳細のグラフ(静的)とは、再生位置との連動・寝落ちエリア・自分の記録の有無で分ける。

## 4. 導線(無料から有料へ)

```
サイト・X(評点と格付け) → インストール → 最初の夜の再生 → 最初の実測の記録
  → 記録5件(傾向が出せる) → ペイウォール → 14日トライアル → 年額
```

- **見る数字:** インストール → 最初の実測(定着の指標)／実測のある人 → 5件到達／ペイウォール表示 → トライアル開始／トライアル → 有料／年額の更新。いまは、どれも実測値がない。1.0 で先に上の3つを取る。
- **ペイウォールを出す場所(3つだけ):**
  1. 記録が5件たまった朝:「あなたの傾向が出せます」(価値がいちばん伝わる。主力)
  2. プレミアムの機能に触れたとき(Player のグラフの鍵、あなた向けの並び)
  3. 設定タブの常設のカード
- **出さない場所:** 起動直後、夜の再生の直前(眠る前に判断を迫らない)。
- **ログインの案内:** 購入の直後と、記録が3件たまったときに「記録を引き継げるようにしませんか」。購入の前には求めない。
- **いちばんの弱点:** 価値の中心(実測・グラフ・あなた向け)が、ヘルスケアに睡眠を記録できる人(Apple Watch など)に限られる。ヘルスケアに睡眠の記録がない人に、朝の自己申告で何をどこまで出すかで、買える人の数が決まる(決めること)。

## 5. 収支の見立て(仮説)

- **1人あたりの手取り:** 年額 1,500円 → 税抜 約1,364円 → Apple の手数料 15% を引いて **約1,160円/年**。月額 200円 → 約155円/月。
  - 手数料 15% は、App Store Small Business Program に入った場合(申請が要る。入らないと1年目は 30%)。
- **固定費(年):** Apple Developer Program 約1.3万円、Supabase は無料枠を超えたら Pro(月25ドル、年 約4.5万円。1ドル150円で計算)。解析は、Claude のセッション判定と手元の文字起こしなので、番組数を増やさない限り増えない。
- **損益の分かれ目:** 固定費 約5.8万円 ÷ 1,160円 = **年額の契約 約50人**。無料から有料への転換を仮に 3% と置くと、使い続けている人が 1,700人前後。転換率は仮の数字で、根拠はない。
- **読み方:** 費用は小さいので、赤字のリスクは低い。事業として効くのは、契約者の数より**その手前(実測の記録が続く人の数)**。そこが増えないと、評点もグラフも育たず、売るものが弱いまま。

## 6. 決まりごと・制約

- **App Store の審査(サブスク):** ペイウォールに、価格・期間・自動更新の説明・利用規約とプライバシーポリシーへのリンク・「購入を復元」を置く。規約の文書がまだない(作る)。
- **アカウント:** アプリ内でアカウントを作れるので、アプリ内から削除できること(`delete-account`。実装済み、未デプロイ)。サブスクは Apple ID に付くので、アカウントを消しても解約にはならない、と削除の確認に書く。
- **ヘルスケアのデータ:** 睡眠のデータを、広告やデータ販売に使わない。「みんなが寝落ちしたあたり」は集計だけを出し、少人数の回は出さない。プライバシーポリシーに、課金とアカウントの項目を足す。
- **番組の作り手:** 広告を飛ばすことを売りにしない(§3.1)。掲載や機能について作り手から申し出があったときの窓口を、サイトに置く。
- **特定商取引法の表記:** 有料で売るので、表記が要るかを確かめる(未確認)。
- **権利の持ち方:** 最初は端末内だけ(StoreKit 2 の購入情報を読む)。プレミアムの機能はすべて端末内で動くので、サーバーで契約を確かめる必要がない。解析のリクエスト(サーバーの費用が出る)を入れるときに、Supabase に契約の状態を持つ(App Store Server Notifications → Edge Function)。そのとき、購入に user_id(`appAccountToken`)を付けておくと結びつけられるので、**購入の処理には最初から付けておく。**

## 7. 実装計画

**ブランチ(2026-11-19 の決定):** プレミアムはバージョン 2 として作る。出来上がるまで `main` に入れず、長く続くブランチ `release/2.0` に集める。機能ごとの PR は `release/2.0` へ向ける。`main` の変更(1.0 の修正など)は、ときどき `release/2.0` に取り込む。2.0 を出すときに、`release/2.0` を `main` へ入れる。

出す順番: **1.0(無料・記録を集める)→ 1.1(課金+本編から始める+グラフ)→ 1.2(あなた向け)→ それ以降**。
1.0 を無料だけで出す理由: 最初の審査を軽くする／グラフの「寝落ちしやすいエリア」とパーソナライズは記録がないと作れない／§4 の数字を先に取れる。

| 段階 | 中身 | 大きさ | 前提 |
|---|---|---|---|
| 0. 土台(1.0) | Apple ログインの実機確認、`delete-account` のデプロイ、`0009` の適用、プライバシーポリシーの更新、ログインの案内(記録3件) | 小 | あなたの操作(Supabase) |
| 1. 課金の土台 | App Store Connect: 有料アプリの契約・銀行と税の登録・サブスクのグループと商品2つ・Small Business Program の申請。アプリ: 契約の状態(`NeochiCore` に判定を置き、テストする)、StoreKit の設定ファイル(手元で購入を試す)、ペイウォール、購入の復元、自分タブのカード、利用規約 | 中 | あなたの操作(契約・口座)。審査に数日 |
| 2. 本編から始める | 秒のずれの実測 → v1(秒で移動+戻すボタン)。アプリが `content_start_*` を読む。解析済みの回に、本編の開始だけを足す(判定のやり直しが要る回数を数える) | 中 | 0009 の適用。判定の精度の確認 |

**進み具合(2026-11-18):** 段階1 のアプリ側は、土台ができた(`Premium.swift`=契約の判断とテスト、`PremiumStore.swift`=StoreKit 2、`PaywallView.swift`=購入の画面、`Config/Neochi.storekit`=手元で購入を試す設定、`terms.html`=利用規約の案)。`PremiumFeatureFlag.enabled = false` で、1.0 には出ない。段階2 のアプリ側も入れた(解析の `content_start_*` を読み、契約中なら本編の位置から再生し、「冒頭に戻す」を出す。列が無い環境では読み飛ばす)。**まだ**: 秒のずれの実測、0009 の適用、解析済みの回への本編開始の追加。残り: App Store Connect の契約・商品、特定商取引法の表記、利用規約の確認、手元での購入の動作確認。

段階1〜3 が、課金を始めるための最小の組。段階2 と 3 は、どちらか片方だけで売り始めない(「Player が賢くなる」と言えるのは、両方あってから)。

## 8. 決めること

1. ~~価格とトライアル~~ → 年額 1,500円・月額 200円・年額に14日、で始める(2026-11-16)。
2. **出す順番。** 1.0 を無料だけで出すか、課金を入れてから出すか。
3. **ヘルスケアに睡眠の記録がない人に、何を出すか。** 朝の自己申告(寝落ちまでの分数)で、あなた向けの並びと傾向を出すか。出すなら、買える人が大きく増える。精度は落ちる。
4. **無料の履歴の長さ。** 直近30日(案)。短くすると有料の理由になるが、原則1(記録は無料)との兼ね合い。
5. **グラフの後半。** 解析は冒頭20〜30分。後半を空白にするか、解析の範囲を伸ばすか(費用が増える)。
6. **「みんなが寝落ちしたあたり」を出す最少の件数**(個人が分からないため。案: 実測5件)。

### 採らなかった案

- いつもの寝落ちで止める(スリープタイマーを、自分の寝落ちまでの分数から自動で決める): 2026-11-16 に、採らないと決めた。

### 有料にしないと決めておくもの

- 回のダウンロード(機内モードで聴く): ポッドキャストアプリでは有料の定番だが、番組そのものへのアクセスに近い(原則3)。置くなら無料。

- 広告。眠る前の画面に置かない。

### 見立て

- 「しおり」は、小さく作れて、毎晩効く。**課金の開始(1.1)に入れる候補**。「本編から始める」と合わせて、「静かに始まる／翌日は続きから」がそろう。
- 「夜の音」は、作るのは重いが、このアプリにしかない売りになる。1.2 以降の目玉の候補。
- 「相性」と「実験」は、払う理由としては中くらいだが、X に出せるので集客に効く。
