# バックログ(MVP のあとに回すもの)

## 昼寝への対応

MVP は「夜に寝る」ことだけを前提にする。昼寝は考慮しない。

決まっていること:
- 睡眠は、時間帯ではなく、ヘルスケアの実測(再生開始以降に最初に「眠っている」と記録された時刻)で判定する。昼寝でも同じ仕組みで測れる。
- 昼寝を夜と分ける区分は作らない。同じ記録として扱う。

やること:
- 昼寝のあとの画面の言葉を直す。「昨夜の結果」「朝の振り返り」が夜前提になっている。
- 昼寝の再生が、就寝時間帯(`BedtimeWindow`)の計算や「昨夜の結果」に混ざらないようにする。
- 「どのくらい寝たか」を記録や評価に使うかを決める。今は入眠までの分数だけ。ヘルスケア側の方針として、睡眠の評価はしない。

## 就寝時間帯での夜の画面の自動表示

`BedtimeWindow`(NeochiCore)はあるが、アプリ側につながっていない。就寝時間帯にアプリを開いたら、夜の画面を出す。初回に就寝時刻を聞く画面も、まだない。

## 記録タブを「傾向を見て、目標を決める場所」にする

方針: 記録タブは、履歴を並べるだけの場所にしない。自分の入眠の傾向を知り、目標を決める場所にする。MVP は最小(日付ごとの結果の一覧)のまま。

置きたいもの:
- **入眠の傾向:** 入眠までの分数の推移(直近7日・30日の中央値)。ふだんの就寝時刻(ヘルスケアの履歴から読んだもの。平日と週末は分ける)。
- **入眠コンテンツの傾向:** 番組・ジャンル別の入眠までの分数。何回目の再生で早く寝られるか。起伏の★との関係。
- **睡眠目標と設定:** 就寝時刻(いまは初回に一度聞くだけで、あとから変える入口がない)、「30分以内に寝落ち」のような目標。

決めておくこと:
- ヘルスケア側の方針は「睡眠の評価(点数、睡眠段階、質)はしない」。傾向は、入眠までの分数と就寝時刻に限る。目標は、本人が決めた数字との差を示すだけで、良し悪しの判定はしない。
- 集計に必要な記録の件数(少ないうちは傾向を出さず、「あと◯晩」と示すか)。
- 傾向の計算は、端末内で行う。Supabase に送るのは、これまでどおり記録だけ。
